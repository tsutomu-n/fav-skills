# UIスキルの選択確認

## 実行方法

同名の別スキルが見えていないことを確認し、各依頼を別の新規セッションで実行する。CLIのJSONL出力から、対象の`ui-design/SKILL.md`を実際に読み込んだかと、その後の参照資料の読み込みを確認する。最終回答にスキル名がないことだけでは未選択と判定できない。

```bash
codex exec --skip-git-repo-check --sandbox read-only --json \
  'SHIKOUの研究結果一覧をスマートフォンで比較しやすくするため、まず現状の確認ポイントを整理して。ファイルは変更しないで。' \
  </dev/null > /tmp/ui-selection.jsonl
```

プロンプトにスキル名や期待結果を書かない。各ケースは対応するプロジェクトのコピーなど安全な場所で実施し、対象の現行資料を利用できるようにする。認識されたスキルの重複、利用モデル、CLIの版、スキルの探索範囲、実行環境、エラーの有無を記録する。通信不能やコマンド失敗を「選択されなかった」と数えない。

## 確認ケース

| 期待 | 依頼の例 |
| --- | --- |
| 選択 | SHIKOUの研究結果一覧をスマートフォンで比較しやすくするため、まず現状の確認ポイントを整理して。ファイルは変更しないで。 |
| 選択 | KeibaCoreの結果一覧で絞り込み条件と解除操作を分かりやすくする案を、現行画面を見て検討して。 |
| 選択 | 西毛建設のWebサイトにお問い合わせ画面を追加する際、既存デザインに合わせるために確認すべきことを整理して。 |
| 選択 | 一覧画面の新しい検索機能をAPIと一緒に設計するとき、表示と操作の確認点を整理して。 |
| 選択しない | SHIKOUの損益計算でFundingを除いた数値が合わない原因を調査して。表示は変更しないで。 |
| 選択しない | KeibaCoreの学習処理がメモリ不足になる原因を調べて。画面は対象外。 |
| 選択しない | 西毛建設サイトのビルドが失敗する原因を調査して。画面の見た目や操作は変更しないで。 |
| 選択しない | このボタンの文言を指定どおり「送信」に直すだけにして。レイアウトや操作の変更は不要。 |

選択されたケースでは、プロジェクトの既存資料を優先し、今回不要な`references/project-guide.md`や`references/sources.md`を機械的に読んでいないかも確認する。選択にはモデル・文脈による揺れがあるため、複数回試して結果を記録し、誤選択や未選択が続く場合に説明文を調整する。
